# White Label

Reviewed: 2026-10-30 against the visible White Label settings forms. This
reference describes general controls, not any organization's saved values.

## Purpose and access

White Label lets an organization personalize the app's brand identity,
appearance, domains, and outgoing email experience where available.
Open the account settings and select **White Label**. Review the availability
and enablement options shown to your account before configuring it.

The current page has three tabs: **Branding & Theme**, **Custom Domains**,
and **Email Configuration**. A configuration summary shows the status of
branding, custom domains, the email provider, and the custom theme.

## Branding & Theme

### Brand Identity

| Field | Purpose |
| --- | --- |
| Brand Name | The organization's display name |
| Logo URL | The image used as the main brand logo |
| Favicon URL | The image used for the browser-tab icon |

1. Open **Branding & Theme** and find **Brand Identity**.
2. Enter the desired display name and provide the logo and favicon through
   the image controls offered by the form.
3. Review the image previews and choose **Save Brand Identity**.
4. Use **Preview Saved Branding** to inspect the saved result.

Example: a fictional agency could display “Example Analytics” with its own
logo. A preview of saved branding reflects saved configuration; save the
intended edits before reviewing it.

### Interface Theme

Choose an available theme using the displayed options. Custom theme controls
include **Accent Color**, **Background Color**, and a **Light/Dark Color
Scheme** where offered. Review the appearance and select **Save Theme
Configuration** to save those choices.

Brand identity and theme have separate save controls. Changing a name or
logo does not mean unsaved theme changes have also been saved.

## Custom Domains

The page distinguishes two purposes:

| Domain type | Purpose |
| --- | --- |
| Application domain | The branded address used to access the app |
| Tracking domain | The branded domain used for analytics tracking scripts |

Open **Custom Domains**, choose the appropriate domain type, and enter the
domain you intend to configure in its form. Follow the on-screen setup
instructions and review the displayed status before treating it as ready.
Use the app's guidance for any required domain-provider work.

The workspace's **Pixel white-labelling** setting is related to tracking;
it is not the same as changing the application's access address. This guide
does not reproduce account-specific domains, DNS values, connection details,
or technical domain-verification procedures.

## Email Configuration

Use this tab to personalize the sending identity and email presentation.

| Visible setting | Purpose |
| --- | --- |
| Enable custom email provider | Choose whether to use the organization's own supported email service |
| Provider Type | Select the supported sending service offered by the form |
| Sender Name | The display name on outgoing email |
| Sender Email | The outgoing From address |
| Reply-To Email | The address intended to receive replies |
| Sending Domain | The domain associated with the email configuration |
| Email Signature | The footer/signature content for branded email |

1. Open **Email Configuration** and review the current options.
2. If using a custom provider, select it and complete its required connection
   fields privately in the app.
3. Review the sender identity, reply destination, and signature.
4. Save using the form's control. Use the test-email action only when you
   intend to send a test to an appropriate recipient.

A display name, sender address, and Reply-To address have different roles.
Previewing branding and sending a test email are also different actions.
This guide contains no sender addresses, recipient addresses, provider
credentials, tokens, passwords, or real email content.

## Scope

These instructions cover the currently visible tabs and their basic use.
They do not promise availability for every plan or role. Follow the app's
visible guidance or in-app support for account-specific setup. Hidden or
unpublished options and internal implementation details are outside scope.
